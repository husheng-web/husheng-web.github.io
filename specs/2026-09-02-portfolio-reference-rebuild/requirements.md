# Portfolio reference rebuild — requirements

## Goal

Replace the previous portfolio interface with an original implementation that uses the supplied reference site for information rhythm and the supplied Humble design reference for the visual system.

## Observable behavior

- `/zh` and `/en` present one coherent, responsive portfolio narrative: identity, profile system, work archive, capability map, proof, and contact finale.
- The global interface uses the supplied warm-paper, ink, graphite, and safety-orange design tokens; shadows and decorative gradients are absent.
- The home page continues to use the verified project registry and only displays owner-approved project facts and media.
- Navigation, locale switching, project routes, mobile menu, keyboard focus, and reduced-motion behavior continue to work.
- Existing `pinlvtu` case-study content remains reachable and no project data is invented.

## Constraints

- Reference-site code, assets, imagery, and copy are not copied or hotlinked.
- The source reference only informs section sequence, hierarchy, archive behavior, and responsive menu pattern.
- The Humble design reference governs colors, shape language, typography roles, and surface treatment.
- Missing identity, experience, contact, resume, and project media stay intentionally pending.

## Out of scope

- New project facts, translations, photographs, email addresses, resume files, CMS, or server-side services.
